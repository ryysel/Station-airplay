# Управление AirPlay через Luna

Shared-controls связывают приёмник с голосовыми командами, громкостью, подсветкой и кнопкой Алисы. Они работают в Go-супервизоре и используют control-enabled Shairport Sync. Сам аудиопоток по-прежнему принимает Shairport Sync.

Для пользователя достаточно [справочника JSON](CONFIGURATION.md) и [руководства по использованию](USAGE.md). Ниже — условия интеграции с хостом и причины ограничений.

## Когда управление запускается

1. Launcher передаёт `--controls-config` с путём к JSON. У пакета v2 файл создаётся в каталоге состояния Luna; корневой legacy-манифест только ссылается на внешний файл.
2. Супервизор проверяет профиль. Старый визуализатор Лайт 2/Миди, AArch64 receiver и профили с неквалифицированным пакетным D-Bus переходят в аудиорежим с сообщением `shared controls disabled`.
3. Для поддерживаемого профиля выполняются проверки API и громкости. Если обязательная возможность недоступна, запуск прекращается с ошибкой. Это отличается от штатного аудиорежима неподдержанного control-профиля.
4. Приёмник открывает локальный D-Bus-интерфейс. Супервизор получает состояние текущего отправителя и доставляет команды через интерфейс Shairport Sync.

Отсутствующий JSON оставляет управление выключенным и не блокирует звук. Неверный JSON останавливает запуск. Сам файл не может включить функцию, которую launcher модели не запускает.

## Авторизация runtime API

| Что передал хост | Действие супервизора | Результат |
|---|---|---|
| Полные `LUNA_API_URL` и `LUNA_API_TOKEN` | Использует только `X-Luna-Token` | Запросы идут в Luna runtime |
| Нет обеих переменных Luna, есть полная пара `YAM_API_URL` / `YAM_API_TOKEN` | Использует только `X-YAM-Token` | Работает совместимый legacy-host |
| Неполная пара или разные значения Luna/YAM | Прекращает запуск | Токен не отправляется в случайно выбранный API |
| Обе полные пары совпадают, кроме завершающего `/` URL | Выбирает Luna | Совместимые алиасы не создают два запроса |

Допустим только HTTP на loopback или собственном адресе интерфейса станции. Прокси окружения и перенаправления не используются. После ошибки авторизации запрос не повторяется с другим заголовком. Переменные `LUNA_API_*` и `YAM_API_*` удаляются из окружения аудиопроцессов.

YAM v2 управляет файлами пакета; runtime-данные выдаёт Luna. Совместимость API сама по себе не создаёт `.yampkg`: [разница сборок](../source/BUILD.md#yap-и-yampkg--разные-результаты).

## Речь и команды

Для `voice` хост должен объявить в `/media` версию `1`, `speech: true` и `commands: true`. Манифест должен разрешать `ipc.speech`, `commands` и конкретные `[commands].phrases`. Для `ducking` нужна речь; для `leds` также требуется `led: true`.

Плагин обрабатывает окончательную фразу с ID запроса. Он проверяет, что текущий отправитель не сменился, и запрашивает у Luna право обработать этот запрос. Затем команда уходит отправителю. Повтор того же запроса, частичное распознавание и старый снимок речи не запускают повторное переключение.

После паузы возможность продолжения сохраняется до 30 минут, пока доступен тот же отправитель. После потери канала или смены отправителя состояние сбрасывается. [Точные команды](../source/TRANSPORT_PHRASES.md) не заменяются поиском ключевых слов в произвольной речи.

## Громкость: Luna и совместимый пакет

При `native_volume: true` плагин сначала читает уровень станции и сообщает его отправителю. Устаревшая громкость телефона не должна перезаписать станцию при подключении. После этого изменения с телефона записываются в станцию, а устойчивые станционные изменения передаются обратно отправителю.

| Backend | Как записывает уровень | Как проверяет |
|---|---|---|
| Luna | `POST /api/volume/set` с `{"percent": N}` | `GET /api/volume`, с учётом шагов до ±5 процентных пунктов |
| Резервный ALSA-путь, пока Luna не отвечает | Системный `amixer set Master N%`, затем попытка unmute | Чтение `Master`; при недоступной ALSA обращается к Luna |
| Legacy `station-volume` | Проверенный shell-launcher `set N` | `check-write`, чтение и firmware-ограничения пакета |
| Пакет через runtime-зависимость Luna | Launcher, возвращённый API зависимости | Те же проверки и подтверждение, без поиска соседних каталогов |

Автоматический выбор всегда предпочитает Luna: только её запись обновляет уровень Quasar, за которым следуют кнопки, кольцо, Алиса и усилитель. Если Luna временно не отвечает, плагин использует `amixer`/`Master` и повторяет Luna через три секунды. Явный `volume_backend: "luna"` отключает резервный ALSA-путь. Для старого API выбирается пакетная совместимость.

Пакетный путь ограничен проверенными прошивками station-volume. Не отключайте его защиту и не вызывайте внутренний native-бинарник напрямую. Недоступная громкость на предварительной проверке может остановить запуск; настройки и диагностика должны указывать выбранный backend.

### Явная зависимость для интегратора

`volume_backend: "package"` и `volume_dependency: "station-volume"` требуют поддержки разрешения зависимостей в Luna. Дескриптор runtime должен объявлять, например:

```toml
[dependencies]
station-volume = "station.volume"
```

Исходный пакет YAM должен объявлять зависимость от `station/volume` и возможность хоста `luna-binary-dependencies-v1`. Это контракт интеграции, а не утверждение о наличии такой комбинации пакетов в реестре.

Перед каждой операцией плагин запрашивает `GET /api/runtime/:id/dependencies/:alias`. Luna должна вернуть включённый совместимый package-owned oneshot-launcher: обычный `sh`, абсолютные пути внутри пакета, без фиксированных аргументов и подмены библиотек. При ошибке API нет отката к ручному поиску соседнего пакета. Пока действует аренда запуска, Luna защищает разрешённые файлы от удаления; перед транзакцией YAM такие плагины нужно остановить.

## Алиса, штатный плеер и индикация

`ducking` использует короткую аренду ослабления потока: при активности Алисы передаётся gain 20% с ограниченным сроком. Плагин продлевает его только при свежих событиях речи. Возврат в ожидание, тайм-аут или остановка снимают ослабление; при потере управления оно истекает в приёмнике. Это не запись в Master и не изменение запомненного уровня телефона.

`native_player` управляет штатным музыкальным плеером через `/system/vendor/quasar/q`. После команд продолжения/переключения он ненадолго удерживает этот плеер на паузе: Алиса тоже могла понять команду и начать свою музыку. Речевой ответ при этом не останавливается.

`alice_button` переключает отправитель между Play/Pause и подавляет случайный запуск штатного плеера после короткого нажатия. Функция требует `native_player`, разрешённую модель и найденное устройство кнопки. Плагин не захватывает клавиатуру эксклюзивно; вне AirPlay и во время разговора остаётся штатное поведение.

Shared-индикация ждёт свежего состояния ожидания Алисы. RGB-кольца используют объявленные возможности хоста. Станция 2 имеет backend для модели `yandexstation_2` и framebuffer строго `89×1`: при другой геометрии запись не включается. Backend уступает чужим кадрам и очищает только собственный совпадающий кадр. Это совместное использование, а не эксклюзивное владение экраном.

Shared-controls не рисуют сегментные часы. Старый renderer Лайт 2/Миди — отдельная ветка.

## Дополнительный мост громкости

`group` задаёт частные IPv4-адреса станций и отдельный 32-байтный ключ. Сокет UDP 43792 открывается только при такой настройке. Перед обменом проверяется текущая живая AirPlay-группа; подпись, время и nonce защищают от подмены и повторной обработки сообщения.

Обмен выполняется по мере доступности участников и не гарантирует атомарное изменение всей группы. Реальный LAN-тест этого моста отдельно не подтверждён. Для синхронного звука AirPlay 2 он не нужен и в штатной поставке выключен.

## Проверки и ограничения

26 октября 2026 года владелец подтвердил голос, кнопки отправителя, двустороннюю громкость и индикацию на Станции 2, Мини 2 и двух Лайт 2. Поздние отчёты фиксируют отдельные сценарии: [26–27 октября](validation/CONTROLS_20261027.md), [1.4.10](validation/CONTROLS_1.4.10_20261028.md), [preplay 1.4.14](validation/2026-10-29-preplay-1.4.14.md).

Тесты Go проверяют команды, D-Bus-сообщения, защиту от повторов и подтверждение уровня. Они не подтверждают слышимое изменение громкости на железе. Новый runtime требует проверки на конкретной колонке, включая старый путь Лайт 2/Миди. AArch64-controls, чистая воспроизводимость сборочного образа и материалы для перелинковки зависимостей остаются отдельными ограничениями: [сборка](../source/BUILD.md), [происхождение runtime](../third_party/README.md).
