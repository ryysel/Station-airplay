# Мини 3: проверка управления 7 ноября 2026

Проверка на живой Мини 3, runtime model ID `yandexmini3` (пакет `bergamot`).
Профиль `bergamot`: PCM `speakers`, приёмник ARMhf на AArch64-ядре;
использована Luna v0.2.24 с описанным ниже исправлением. Версии YAM,
ОС и приложения отправителя для этого сеанса не зафиксированы.
На устройстве установлен пакет 2.1.1; для этой проверки в локальном launcher
включён `--controls-config`. Это отдельная проверка экспериментального
управления, а не подтверждение настроек опубликованного пакета.

## Возможности и границы индикации

Живой `/api/device` объявляет `led.ring.rgb`, `led.ring.6`,
`led.pattern.v1`, `led.sysfs` и `display.clock.segment.v1`.
Runtime сообщает шесть RGB-светодиодов; в sysfs это
`bergamot:red:logo0..5`, `bergamot:green:logo0..5` и
`bergamot:blue:logo0..5`. `/media` подтверждает `led: true` и
`led_count: 6`. Этого достаточно для существующего общего RGB-backend,
отдельный аппаратный backend Мини 3 не требуется.

Профиль Мини 3 имеет `ui: false`: PCM-визуализатор и отрисовка сегментных
часов не запускаются. Текущее shared-управление задаёт шести RGB-каналам
постоянный бирюзовый цвет во время сеанса, уступает индикацию Алисе и
освобождает её после отключения отправителя. При `led_level: 200` цвет
кадра — `#00c864`. Это индикация сеанса на светодиодах логотипа/кнопки,
а не анимация спектра на часах; часами продолжает управлять прошивка.

Во время отдельного чтения все 18 RGB-каналов имели яркость 0. Этот
снимок не был сопоставлен с подтверждённым активным сеансом и свежим
состоянием ожидания Алисы, поэтому он не доказывает ни исправность, ни
неисправность физической индикации AirPlay. Произвольные тестовые кадры
не отправлялись.

## Что осталось проверить

- Во время подтверждённого AirPlay-сеанса сопоставить физическую
  подсветку с воспроизведением, паузой, ответом Алисы и отключением.
- Повторное подключение, холодный запуск, мультирум и длительную
  стабильность этот отчёт не подтверждает.

## Исправление скачка громкости

Причина подтверждена в Luna: отсутствует слушатель старого
`volume_manager` на порту 9922, а точная прошивка Мини 3 отсутствовала
в `quasar_volume::verified_build`. Поэтому Luna переходила на ALSA.
Независимое чтение штатного `stereo_pair` показало логические 5% при
ответе старой Luna 13% (ALSA Master 33/255). Кнопка станции меняла
сохранённый логический уровень Quasar, что приводило к скачку.

Использованы исходники [Luna v0.2.24](https://github.com/nyakokitsu/luna/tree/v0.2.24),
commit `7a9d503`. Исправление в `src/quasar_volume.rs` Luna разрешает существующий
штатный протокол только для полного build
`0.369.1.50.4794652521.20261021.117` и отдельного NUL-разделённого
DT-элемента `yandex,bergamot`. На устройстве также присутствуют
`yandex,bergamot-evt1` и `amlogic, axg`.
Формат протокола не менялся: чтение `stereo_pair` (9921), запись
`VolumeSet254` через `iohub_clients` (9910), подтверждение штатным
потоком состояния. До установки независимая проверка получила
подтверждения 5 → 0 → 5%.

### Сборка и проверки

В Podman Rust 1.99.1 / aarch64 musl новый тест сначала упал без
исправления, затем прошёл с ним. `cargo test --workspace --locked`:
136 passed, 0 failed, 1 ignored. Пропущен существующий
`packaged_manifest_read_cost`: отдельный аудит производительности,
которому нужен готовый descriptor пакета. Два существующих предупреждения
dead_code относятся к Bluetooth helper-функциям.

Собран именно `cargo build --release --locked -p luna-yandexmini3`:
статический ELF ARM AArch64, установлен под штатным именем `luna`.
Универсальный бинарник сначала показал model=unknown и был откачен;
итоговый вариант станции подтверждает `yandexmini3`, шесть RGB-каналов
и сегментные часы. Отдельный smoke-процесс Luna заменяет рабочий экземпляр
даже с другим портом/каталогом; после проверки восстановлен один рабочий
процесс через существующий init.

Исходный бинарник:
`83daa222410a3734f221124e6a739c8378974deaf057e2e6cb995c165c158bbd`.

Установленный исправленный бинарник:
`53d4d87a2959201b6ab7f0db4b28371a40e98f174a0095ebac435cda601324db`.

Резервная копия:
`/data/yam/pkgs/yam/luna/0.2.24/bin/luna.before-mini3-volume-20261107-145612`.

Luna автоматически заменила первый локальный патч публичным релизом и
при этом потеряла параметры YAM. Поэтому через поддерживаемую настройку
`[updates] enabled = false` автообновление временно отключено до включения
патча в upstream. Копия прежних настроек:
`/data/yam/var/luna/data/settings.toml.before-mini3-volume-20261107-1502`.
Init не изменялся. Итоговый запуск сохраняет `--yam-root /data/yam`
и `--yam-run /tmp/yam`; AirPlay снова запущен с controls-config.

### Проверка установленной сборки

Ответы рабочего API независимо сопоставлены с логическим состоянием
Quasar через 9921, без использования ALSA как доказательства:

| Запрошено API | Ответ set | Независимый GET | Quasar |
|---|---|---|---|
| 5% | 5% | 5% | 5% |
| 0% | 0% | 0% | 0% |
| 5% | 5% | 5% | 5% |

Итоговый уровень оставлен 5%. После более чем одного интервала первоначальной
проверки обновления hash исправленной сборки и штатные параметры запуска
сохранились. После установки владелец сообщил: «похоже теперь все работает нормально».
Это подтверждение устранения наблюдавшегося скачка; отдельный подробный
прогон каждого направления кнопок, холодный старт и длительный soak не заявляются.
