# Настройка Station-airplay

Настройки управления читаются при запуске. После изменения файла [перезапустите плагин через Luna](INSTALLATION.md#перезапуск-и-остановка). Доступность функций зависит от [модели и режима](SHARED_MODELS.md): `true` в JSON не добавит отсутствующий D-Bus-мост или поддержку кнопки.

## Файл пакета YAM v2

Launcher хранит файл в `$LUNA_PLUGIN_STATE/airplay-controls.json`. В типичной установке это:

```text
/data/yam/var/luna/data/plugins/plugin-state/airplay.airplay-luna/airplay-controls.json
```

При первом запуске launcher создаёт настройки. Следующие запуски сохраняют непустой файл; пустой файл launcher создаёт заново. На станции с поддержкой управления и штатным Quasar итоговая конфигурация обычно выглядит так:

```json
{
  "voice": true,
  "native_volume": true,
  "ducking": true,
  "leds": true,
  "led_level": 200,
  "native_player": true,
  "alice_button": true
}
```

Шаблон пакета включает `native_player` и `alice_button` для `yandexmini_2`, `yandexplum` и `yandexstation_2`. У остальных моделей оба поля `false`; `native_player` может включить лаунчер при наличии штатного Quasar CLI. Runtime отключает флаг, если нет CLI, `voice` или найденной кнопки.

**Значения пакета и Go-программы различаются.** Launcher создаёт показанный файл, но Go-декодер не дополняет пользовательский JSON: пропущенное логическое поле становится `false`. Если файл по `--controls-config` отсутствует, приёмник запускается без shared-управления с предупреждением в логе. Неверный JSON останавливает запуск.

## Поля JSON

| Поле и условие | Что меняет | Если не задано / поведение по умолчанию |
|---|---|---|
| `voice`: `true` / `false` | Передаёт точные распознанные команды плееру отправителя | В JSON — `false`; шаблон v2 — `true`. Нужны речь и команды в API Luna. |
| `native_volume`: `true` / `false` | Связывает ползунок отправителя с громкостью станции; проверяет запись чтением уровня | В JSON — `false`; шаблон v2 — `true`. Без него приёмник регулирует своё ослабление поверх уровня станции. |
| `ducking`: `true` / `false` | При активности Алисы снижает уровень только AirPlay-потока; после ответа возвращает его | В JSON — `false`; шаблон v2 — `true`. Нужны события речи Luna, даже если `voice` выключен. |
| `leds`: `true` / `false` | Включает индикацию AirPlay, когда Алиса свободна и модель поддерживает вывод | В JSON — `false`; шаблон v2 — `true`. Не включает сегментные часы. |
| `led_level`: целое `0..255` | Задаёт яркость shared-индикации | Шаблон v2 — `200`. Пропуск или `0`: `200` для framebuffer Станции 2, `16` для RGB-колец. Для выключения используйте `leds: false`. |
| `native_player`: `true` / `false` | После продолжения/переключения удерживает штатный музыкальный плеер на паузе, чтобы рядом с AirPlay не началась вторая музыка | В шаблоне — `true` для Станции 2, Мини 2 и Лайт 2, иначе `false`; лаунчер может включить при наличии `voice: true` и `/system/vendor/quasar/q`. Если CLI нет, runtime отключает функцию с записью в лог. |
| `alice_button`: `true` / `false` | Короткое нажатие кнопки Алисы отправляет Play/Pause текущему AirPlay-плееру вне разговора с Алисой | В шаблоне — `true` для Станции 2, Мини 2 и Лайт 2, иначе `false`. Runtime отключает только эту функцию, если нет `native_player` или найденной кнопки. |
| `volume_backend`: `"luna"` или `"package"` | Выбирает, кто записывает громкость станции | Пропуск или пустая строка: Luna для URL `/api/runtime/<id>`, пакетный путь для legacy YAM. При заданном `volume_dependency` выбирается пакетный путь. |
| `volume_dependency`: строка | Запрашивает у Luna launcher зависимости `station-volume` по объявленному псевдониму | Не задано: зависимость через API не запрашивается. Псевдоним: 1–64 символа `a-z`, `0-9`, `-`, `_`. Допустимо только с `native_volume: true` и без принудительного `volume_backend: "luna"`. |
| `group`: объект | Включает дополнительный обмен громкостью между явно заданными станциями | Не задано: выключен; AirPlay 2 multiroom продолжает работать. |

Допустимы только перечисленные поля. Комментарии, неизвестные ключи и лишний объект после JSON приводят к ошибке чтения. Чтение ограничено примерно 16 КиБ; держите файл меньше этого размера. Булевы значения записывайте без кавычек: `true`, а не `"true"`.

### Кто управляет громкостью

В обычном режиме Luna принимает уровень через `/api/volume/set`. Плагин затем читает фактический уровень. Это позволяет заметить отказ записи и учесть шаги громкости станции.

При автоматическом выборе владельцем громкости остаётся Luna `/api/volume`: только её запись обновляет логический уровень Quasar, который используют кнопки, кольцо, Алиса и усилитель. Если на холодной загрузке Luna ещё не отвечает, плагин временно пишет в системный `amixer` (контрол `Master`) и через три секунды снова пробует Luna. Принудительное `volume_backend: "luna"` оставляет только API Luna.

Пакетный backend нужен для старой схемы `station-volume`. При явном `volume_dependency` Luna должна разрешать объявленную зависимость через runtime API. Это настройка интегратора: одного имени в JSON недостаточно. [Подробности](SHARED_CONTROLS.md).

### Необязательный объект `group`

Мост передаёт изменения громкости между участниками той же текущей AirPlay-группы. Он не создаёт группу и не синхронизирует звук. В поставляемой конфигурации он выключен; аппаратная проверка моста отдельно от обычного мультирума не подтверждена.

| Поле | Что задаёт | Требование при включённом `group` |
|---|---|---|
| `bind` | Локальный адрес UDP-сокета | Явный частный IPv4 этой станции; порт `43792` фиксирован |
| `peers` | Адреса остальных станций | От 1 до 32 разных частных IPv4, без собственного адреса |
| `key_file` | Путь к общему секретному ключу | Общий для участников обычный файл ровно 32 байта, недоступный группе и другим пользователям, например с правами `0600` |

У полей нет автоматических значений. Сообщения проверяются по подписи, времени и текущей группе. Ошибочная настройка моста может остановить shared-управление. Для моста обязателен `native_volume: true`. Для обычного прослушивания оставьте `group` незаданным.

## Флаги Go-супервизора

Флаги задаёт launcher или манифест. В обычной установке v2 менять их не нужно.

| Флаг | Что меняет | Без флага |
|---|---|---|
| `--shared-audio` | На Лайт 2 выбирает PCM `speakers` без старого визуализатора часов; даёт shared-управлению владеть индикацией | При наличии сегментных часов Лайт 2 использует прежний визуализатор. Без возможности часов выбирается shared-путь. На других моделях профиль определяется model ID. |
| `--controls-config PATH` | Читает JSON управления | Shared-управление выключено. Если путь задан, а файла нет, звук запускается с предупреждением. |
| `--version` | Печатает версию и завершает программу | Начинается обычный запуск, которому нужен хост Luna/YAM |

Сегментный визуализатор Лайт 2 и shared-индикация не могут одновременно владеть экраном. Если профиль управления не квалифицирован, плагин пишет `shared controls disabled` и продолжает в аудиорежиме. Поддерживаемый профиль с недоступными обязательными API может завершиться на предварительной проверке.

Супервизор создаёт `shairport.conf` заново. Правки в `/run/station-airplay/` не сохраняются между запусками.

## Переменные среды и старые файлы

| Поле или файл | Что меняет | Без значения |
|---|---|---|
| `LUNA_API_URL` + `LUNA_API_TOKEN` | Адрес и авторизация runtime API конкретного запуска | Передаются Luna. Ручной запуск без runtime-данных завершится ошибкой. |
| `YAM_API_URL` + `YAM_API_TOKEN` | Совместимость с runtime API старого YAM | Используются, только если нет обеих переменных Luna. Неполные или конфликтующие пары отклоняются. |
| `LUNA_PLUGIN_STATE` | Каталог состояния для launcher пакета v2 | Задаётся Luna; вручную экспортировать переменную в SSH-сессии не нужно. |
| `PLUM_TZ` | Часовой пояс старого визуализатора Лайт 2/Миди | Далее читается `/data/shairport/tz`, затем `MSK-3` (UTC+3). Поддерживаются простое POSIX-смещение вроде `UZT-5` и IANA-зона при доступной базе зон. |
| `STATION_AIRPLAY_QUASAR` | Выбор `on`/`off` для Quasar на старом FIFO-пути Миди | Далее читается `/data/shairport/quasar`; без файла — `on`. `off` останавливает Алису на время работы приёмника. [Подробнее](MIDI.md). |
| `LUNA_VOLUME_MANAGER_ADDR` | Переопределяет адрес для проверки доступности volume manager | Проверяется `volume_manager.port` из `/system/vendor/quasar/quasar.cfg`. Обычно менять не нужно. |

Runtime-токены создаёт хост. Не сохраняйте их в JSON, репозитории или issue. Супервизор не передаёт `LUNA_API_*` и `YAM_API_*` аудиопроцессам.

## Старый пакет `.yap`

Корневой `plugin.toml` запускает бинарник с `--shared-audio --controls-config ../../airplay-controls.json`. Путь разрешается относительно каталога плагина, поэтому файл находится в общем каталоге данных старого YAM рядом с `plugins/`. Launcher из пакета v2 этот файл не создаёт.

Если совместимый speech-enabled YAM настроен, минимальный файл для голоса без станционной громкости и подсветки:

```json
{
  "voice": true,
  "native_volume": false,
  "ducking": true,
  "leds": false
}
```

Пропущенные поля выключены. Разрешения и точные фразы должны быть объявлены в манифесте. Остановите старый сервис, дождитесь освобождения процессов и запустите снова штатными командами вашей версии YAM.
