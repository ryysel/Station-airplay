# Установка Station-airplay

Для YAM v2 устанавливайте `airplay/airplay-luna`. YAM выбирает пакет для платформы, а Luna запускает его как плагин. Команды старого YAM и архивы `.yap` приведены отдельно в конце файла.

## Перед установкой

| Что проверить | Почему это нужно |
|---|---|
| Станция подготовлена для YAM и доступна по SSH | Репозиторий не содержит универсального способа открыть доступ к штатной станции. |
| Клиент `yam` — 0.2.5 или новее | Более ранний клиент не понимает `postinstall` и отклоняет пакет с ошибкой `unknown field postinstall`. Флага `--version` у `yam` нет: если пакет не ставится с этой ошибкой, обновите `yam`. |
| Выбрана нужная станция или платформа YAM | Локальный `.yampkg` имеет конкретный `target`; пакет другой платформы не подойдёт. |
| Нет второго AirPlay-приёмника и его автозапуска | Старый Shairport Sync или NQPTP займёт порты, и новый приёмник откажется стартовать. |
| Сохранены рабочий пакет и конфигурация | Они понадобятся для возврата к прежней версии. |

Готовый пакет содержит приёмник и его дополнительные библиотеки. Go, Python и инструменты сборки на колонке не нужны. Пакет использует штатный Linux и ALSA — звуковую систему станции. Обычный компьютер с Windows или macOS не заменяет эту среду выполнения.

## Сеть

Устройство Apple должно видеть объявления станции и подключаться к ней напрямую. Начните с одной локальной сети без изоляции Wi-Fi-клиентов. Одного разрешённого TCP-порта для всего AirPlay недостаточно.

| Трафик | Что делает | Как используется |
|---|---|---|
| UDP 5353, mDNS | Обнаружение приёмника без ввода IP | Объявления `_airplay._tcp` и `_raop._tcp` должны доходить до отправителя. |
| TCP 5000 | Управляющее соединение RTSP | У профилей с прямым общим ALSA-выходом, включая штатный режим Лайт 2. |
| TCP 7000 | То же для Миди | Профиль Миди использует порт AirPlay 2 по умолчанию. |
| UDP 319 и 320 | Синхронизация времени PTP | Их использует NQPTP. |
| UDP 9000 | Временные метки AirPlay 2 | Shared-путь проверяет, свободен ли порт, до старта приёмника. |
| Дополнительные TCP/UDP-порты сеанса | События и аудио | Shairport Sync выделяет их при подключении. Номера смотрите в логе приёмника и активных сокетах. |
| HTTP 8099, обычно `127.0.0.1` | API Luna | Нужен локально для управления плагином; это не порт музыки с телефона. |
| UDP 43792, только при настройке `group` | Дополнительный мост громкости | По умолчанию выключен; обычному мультируму не нужен. |

На VLAN одного mDNS-ретранслятора мало: после обнаружения отправитель должен достичь объявленного адреса и портов сеанса. Разрешайте обмен внутри доверенной сети. Проброс портов в интернет для AirPlay не нужен.

## Установка из реестра YAM v2

Выполните команды там, где клиент YAM уже настроен на нужную станцию. Если используете `--platform` и `--profiles`, сохраняйте эти параметры во всех командах YAM.

1. Добавьте реестр. Команда сохраняет его адрес и публичный ключ проверки подписей:

   ```sh
   yam registry add official https://repo.yse.wtf/v2 \
     --key ed25519:5Rz8F47uftWVU5kLgWYhprkEZ4rpP2kecUge/a7KQas=
   ```

2. Установите пакет:

   ```sh
   yam install airplay/airplay-luna
   ```

   Пакет рекомендует `yam/luna >=0.2.14`, но YAM не устанавливает рекомендации автоматически: в плане установки есть только сам пакет. Если Luna ещё не установлена, выполните `yam install yam/luna`.

   Фоновый установщик также включает настройку Luna `allow_plugin_binaries`. На BusyBox он может изменить `settings.toml` и перезапустить Luna с её прежними аргументами, чтобы разрешение вступило в силу. Ход действий виден в `/tmp/airplay-postinstall.log`.

3. Откройте интерфейс Luna. Найдите `airplay.airplay-luna` и дождитесь состояния `running`.

   После распаковки `postinstall` запускает фоновое включение. Сообщение `scheduled ... start in a detached worker` означает, что установка завершилась, а включение продолжается. Процесс повторяет включение около 20 минут, пока Luna становится доступной и плагин запускается. Затем пакет останется установленным; включите его в Luna после запуска хоста.

4. На станции проверьте слушающий порт:

   ```sh
   netstat -ltn | grep -E ':(5000|7000)[[:space:]]'
   ```

   Для большинства моделей ожидается `5000`, для Миди — `7000`. Порт подтверждает, что приёмник слушает подключения. Затем выберите колонку в AirPlay и проверьте звук: [использование](USAGE.md).

После успешного включения Luna сохраняет выбор и запускает плагин при следующем старте. Для автозапуска после перезагрузки станции сама Luna тоже должна запускаться при загрузке.

## Установка из файла `.yampkg`

Скачайте архив своей платформы из [Releases](https://github.com/ryysel/Station-airplay/releases). Например, для Станции 2 в релизе 2.0.8:

```sh
yam install ./station-airplay-2.0.8-yandexstation_2.yampkg
```

YAM проверит платформу и распакует пакет. Включение в Luna работает так же, как при установке из реестра. Для другой станции выберите соответствующий файл релиза; не переименовывайте чужой архив и не подменяйте model ID.

## Где находятся файлы

Пути относятся к типичной установке YAM в `/data/yam`. У другого корня YAM пути будут отличаться.

| Путь | Что хранится |
|---|---|
| `/data/yam/share/luna/plugins/airplay.airplay-luna/` | Runtime: launcher, приёмник, библиотеки и манифест Luna |
| `$LUNA_PLUGIN_STATE/airplay-controls.json` | Настройки пользователя; launcher сохраняет их между запусками |
| `/data/yam/var/luna/data/plugins/plugin-state/airplay.airplay-luna/` | Обычный каталог состояния; здесь также ищите `runtime.log` |
| `/tmp/airplay-postinstall.log` | Ход фонового включения после установки |
| `/run/station-airplay/` | Временная конфигурация и логи shared-приёмника; создаются заново при запуске |

`$LUNA_PLUGIN_STATE` передаётся процессу плагина. В SSH-сессии переменной может не быть. Фактический каталог состояния смотрите в установке Luna.

## Перезапуск и остановка

После правки JSON выключите плагин в Luna, дождитесь остановки и включите снова. Старый процесс должен освободить порты. Текущий AirPlay-поток прервётся.

При обычном локальном адресе API те же действия можно выполнить **на станции**:

```sh
wget -q -O - --header='Content-Type: application/json' --post-data='{}' \
  http://127.0.0.1:8099/api/plugins/airplay.airplay-luna/service/disable
```

Дождитесь состояния остановки в Luna, затем:

```sh
wget -q -O - --header='Content-Type: application/json' --post-data='{}' \
  http://127.0.0.1:8099/api/plugins/airplay.airplay-luna/service/enable
```

Если API Luna слушает другой адрес или требует дополнительную авторизацию, используйте её интерфейс. Не подставляйте runtime-токен в публичные команды или отчёты.

## Старый YAM и формат `.yap`

`scripts/package.py` и текущий CI создают один `.yap`. Его ID — `station-airplay`; у пакета Luna из реестра v2 ID — `airplay.airplay-luna`. Это разные способы установки и управления.

Для совместимого старого YAM с командами `enable`, `ps` и `logs`:

```sh
yam install ./dist/station-airplay-2.0.8.yap
yam enable station-airplay
yam ps
yam logs station-airplay
```

Эти команды выполняются на компьютере с настроенным старым клиентом YAM. Они не заменяют включение в Luna для пакета v2. У старого пакета нет launcher, который создаёт пользовательский JSON: [настройка legacy-пакета](CONFIGURATION.md#старый-пакет-yap).

Ручные `support/prepare-host.sh`, `restore-host.sh` и `migrate-shared.sh` относятся к прежним установкам с конкретной раскладкой файлов. Прочитайте скрипт перед применением; современный shared-путь сам создаёт частную D-Bus-шину и не требует этих процедур.
