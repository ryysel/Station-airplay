# Station AirPlay 2.0

AirPlay 2 для Яндекс Станций под управлением [Luna](https://github.com/nyakokitsu/luna).
Один плагин, общий звук с Алисой, голосовое управление и установка одной командой
из реестра YAM v2.

Для **Mini 2 с обычным YAM 0.2.x без Luna** предлагается явный
[`--standalone` режим общей громкости](docs/STANDALONE_VOLUME.md): ползунок
отправителя и Алиса используют один штатный уровень, а индикацию изменения
рисует прошивка. Путь к `station-volume.sh` передаётся параметром; его точные
проверки платы и прошивки сохраняются. Это исходная интеграция, не новый
релиз пакета или installer.

В этом режиме можно отдельно включить
[`voice_pause_only=true`](docs/STANDALONE_VOLUME.md#голосовые-пауза-и-стоп):
«Алиса, пауза» и «Алиса, стоп» ставят AirPlay-плеер на паузу. Проверено
владельцем на Mini 2 с Яндекс Музыкой в Safari; возобновление — кнопкой
браузера. Общий `voice` остаётся выключенным, остальные фразы Алисы
обрабатываются штатно.

## Что нового в 2.0

- **Установка одной командой** из реестра YAM v2: `yam install airplay/airplay-luna`.
  Вместе с плагином ставится и Luna, если её ещё нет.
- **Автозапуск.** Пакетный хук после установки сам включает плагин в Luna —
  отдельно ходить в веб-интерфейс не нужно. При следующей загрузке станции
  плагин стартует вместе с Luna.
- **Голосовое управление включено по умолчанию** там, где есть общее
  управление (Станция 2, Мини, Мини 2, Лайт, Лайт 2): «поставь на паузу»,
  «следующий трек», «продолжи». Алиса при этом остаётся рабочей.
- **Громкость принадлежит Luna.** Слайдер отправителя ходит через
  `/api/volume`; если Luna не отвечает, плагин пишет в ALSA сам.
- **D-Bus без внешних утилит.** Собственный клиент сам делает handshake на
  приватной шине, затем на системной; `dbus-send` больше не требуется.
- **Все актуальные платы**: Станция 2, Миди, Станция 3, Лайт, Лайт 2, Мини,
  Мини 2, Мини 3.

| Лайт 2 | `plum`, `yandexplum` | да | да | живая колонка (с часами и без) + эмулятор |
| Мини | `yandexmini` | да | пока нет (audio-only) | эмулятор: установка, запуск, автостарт |

| Мини 3 | `bergamot` | да | пока нет (audio-only) | эмулятор: установка, запуск, автостарт |
| Мини 3 Про | `yandexmini_3_pro` | нет сборки | — | не проверялась |

«Живая колонка» — обычная станция из парка, «эмулятор» — стенд kuyase.
Голос на Миди, Станции 3 и Мини 3 выключен не случайно: их launcher'ы пока
запускаются в audio-only режиме, без `--controls-config`. На оригинальном Мини
launcher controls передаёт, но профиль для его D-Bus-моста не квалифицирован,
поэтому приёмник сам переходит в audio-only и пишет причину в лог, а не падает.

Эмулятор подтверждает установку из пакета, запуск, режим и автостарт. Он не
проверяет реальный звук, микрофон Алисы, физические LED и передачу потока
родному плееру: в стенде Quasar работает в заглушечном режиме.

На всех моделях звук общий с Алисой: приёмник подмешивается в тот же микшер,
поэтому голосовой ассистент продолжает работать во время воспроизведения.
Профиль выбирается автоматически по model ID, который отдаёт YAM.

Как принять установку на своей станции: [docs/CHECK_ON_YOUR_SPEAKER.md](docs/CHECK_ON_YOUR_SPEAKER.md).

## Мультирум

Групповое воспроизведение идёт штатным AirPlay 2 multiroom отправителя:
приёмник — Shairport Sync, синхронизацию часов держит NQPTP. Отдельного
«группового» режима в плагине нет и не требуется.

Проверено на живой колонке 27.10.2026: сначала обе Лайт 2, затем все четыре
станции. Эха и слышимого рассинхрона не было, пауза/продолжение/следующий
трек с телефона работают, колонку можно исключить и вернуть, ответ Алисы на
одной колонке не останавливает музыку на остальных.

Это слуховая приёмка владельца, а не инструментальное измерение синхрона:
длительный soak и замер дрейфа не проводились. Подробности —
[`docs/validation/CURRENT_PAIR_20261027.md`](docs/validation/CURRENT_PAIR_20261027.md).

Групповой ползунок громкости отправителя не двигает все колонки сразу:
peer-мост групповой громкости выключен, громкость настраивается на каждой
колонке отдельно. Это сознательное решение владельца, а не дефект.

## Установка

### Требования

- Станция с прошивкой, на которой работает YAM, и доступ по SSH.
- `yam` **0.2.5 или новее** на компьютере или на самой станции. Более старые
  клиенты не понимают поле `postinstall` в манифесте и откажутся ставить пакет.
- Свободные порты 5000 (или 7000 на Миди) и 8099 под Luna.

### Одна команда

Добавьте реестр (один раз) и поставьте плагин:

```sh
yam registry add official https://repo.yse.wtf/v2 \
  --key ed25519:5Rz8F47uftWVU5kLgWYhprkEZ4rpP2kecUge/a7KQas=

yam install airplay/airplay-luna
```

Всё. Пакет сам:
1. поставит Luna нужной версии, если её нет;
2. распакует плагин в `share/luna/plugins/airplay.airplay-luna`;
3. передаст включение плагина отсоединённому воркеру, который дождётся API
   Luna и включит плагин.

Через несколько секунд станция появится в меню AirPlay. Проверить, что приёмник
поднялся:

```sh
netstat -ltn | grep -E ':(5000|7000)'
```

Если Luna в момент установки не запущена, воркер ждёт её около 20 минут и
включает плагин, как только API отвечает. Если Luna не поднялась и за это
время, пакет останется установленным, но выключенным: включите плагин в
интерфейсе Luna. После успешного включения выбор сохраняется в базе Luna и
переживает перезагрузку.

### Установка из файла

Скачанный `.yampkg` для своей модели ставится так же:

```sh
yam install ./station-airplay-2.0.4-yandexstation_2.yampkg
```

Артефакты для конкретных плат лежат в разделе Releases и в реестре
`airplay/airplay-luna`. Пакет для одной модели не встанет на другую — в
манифесте зафиксирован `target`.

## Настройка

После первого запуска Luna создаёт файл:

```text
$LUNA_PLUGIN_STATE/airplay-controls.json
```

На живой прошивке это обычно
`/data/yam/var/luna/data/plugins/plugin-state/airplay.airplay-luna/`.

Значения по умолчанию:

```json
{
  "voice": true,
  "native_volume": true,
  "ducking": true,
  "leds": true,
  "led_level": 200,
  "native_player": true,
  "alice_button": true
}
```

| Поле | По умолчанию | Что делает |
|---|---|---|
| `voice` | вкл | голосовые команды через runtime Luna (`ipc.speech` + `commands`) |
| `native_volume` | вкл | слайдер отправителя двигает громкость станции через `/api/volume` |
| `leds` | вкл | индикация на кольце или экране, где она поддерживается |
| `ducking` | вкл | приглушает AirPlay, пока Алиса слушает и говорит |
| `native_player` | вкл при Quasar | после паузы отдаёт воспроизведение штатному плееру Quasar |
| `alice_button` | вкл при Quasar | пауза по физической кнопке Алисы |

`native_player` и `alice_button` включаются не «слепо»: при первом запуске
launcher проверяет, есть ли штатный Quasar CLI (`/system/vendor/quasar/q`) и
поддерживает ли модель кнопку Алисы. На живой колонке с полной прошивкой
включается весь набор; в эмуляторе без Quasar остаются голос, громкость,
подсветка и ducking. Если флаг всё же окажется включённым на плате без
Quasar, preflight отключит только его — приёмник продолжит работать.

`ducking` меняет поведение Алисы: она приглушает AirPlay, пока слушает и
говорит. Если это не нужно, выключите флаг вручную.

Уже созданный файл launcher не перезаписывает: свои правки сохраняются.

После правки файла перезапустите плагин:

```sh
wget -q -O - --post-data= \
  http://127.0.0.1:8099/api/plugins/airplay.airplay-luna/service/disable
wget -q -O - --post-data= \
  http://127.0.0.1:8099/api/plugins/airplay.airplay-luna/service/enable
```

## Как это работает

```text
iPhone/Mac → AirPlay 2 → Shairport Sync → ALSA (общий микшер) → динамики
                                        └→ PCM FIFO → supervisor → Luna API
                                                                 ├→ голос
                                                                 ├→ громкость
                                                                 └→ LED/дисплей
```

- **Shairport Sync** принимает поток и декодирует его в PCM.
- **Supervisor** на Go держит дочерние процессы, синхронизирует громкость,
  отправляет голосовые команды и рисует индикацию через API Luna.
- **Avahi** публикует `_airplay._tcp`; **NQPTP** участвует в синхронизации
  AirPlay 2.
- Плагин не трогает GPIO и регистры LED напрямую — только документированный
  runtime API.

## Сборка из исходников

Нужен Go 1.23+. Полная сборка runtime и сторонних библиотек описана в
[source/BUILD.md](source/BUILD.md).

```sh
cd source
go test ./...
go vet ./...
GOOS=linux GOARCH=arm GOARM=7 CGO_ENABLED=0 \
  go build -buildvcs=false -trimpath -ldflags='-s -w' \
  -o ../bin/station-airplay .
```

Упаковка legacy `.yap` (для старого YAM):

```sh
./scripts/package.sh
```

Пакеты `.yampkg` для реестра YAM v2 собираются отдельным инструментом поверх
этих же бинарников и runtime-библиотек.

## Диагностика

**Станция не видна в AirPlay.** Проверьте, что приёмник слушает порт и что
mDNS проходит между сетями (VLAN/гостевой Wi-Fi часто режут multicast).

```sh
netstat -ltn | grep -E ':(5000|7000)'
tail -n 50 /data/luna/plugins/plugin-state/airplay.airplay-luna/runtime.log
```

**Нет звука.** Плагин играет в общий микшер станции; проверьте, что не запущена
вторая реализация AirPlay и что `amixer scontrols` видит нужный контрол.

**Не работают голосовые команды.** Luna должна отдавать в `/media` возможности
`speech` и `commands`. Если пакет ставился на старую Luna, обновите её и
перезапустите плагин.

**Плагин не стартует после установки.** Включите его вручную:

```sh
wget -q -O - --post-data= \
  http://127.0.0.1:8099/api/plugins/airplay.airplay-luna/service/enable
```

Больше сценариев — в [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md).
